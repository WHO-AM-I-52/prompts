## KITEZH MAIN 2.23
**Дата:** 25 августа 2026

### Безопасная передача изменений и проверка результатов

- Добавлен режим **«Полный файл для замены»**: полный исходный текст можно выдавать только после получения читаемого актуального содержимого именно этого файла через GitHub MCP или из приложенного пользователем файла.
- Уточнено, что SHA коммита, blob SHA файла, метаданные, diff и статус `downloaded` сами по себе не подтверждают доступность актуального полного текста файла.
- Добавлены требования указывать путь, базовую ветку или commit SHA, blob SHA файла при наличии и выбранный способ передачи изменения.
- Запрещена реконструкция полного файла по фрагментам, старому контексту или предполагаемой структуре, если актуальный текст файла не был прочитан.
- Добавлен сценарий **`CODER — локальная правка пользователем`** для запросов на код, diff, полный файл для замены или commit message без запроса на GitHub write.
- Для локальной правки закреплены три формата передачи: полная замена файла, точечная замена уникального фрагмента и unified diff; для небольших изолированных изменений предпочтителен unified diff.
- Уточнено, что commit message передаётся отдельно от кода, а commit не может считаться созданным без подтверждения GitHub MCP.
- Добавлен режим read-only проверки коммита, который пользователь прислал по ссылке или SHA.
- В отчёте о пользовательском коммите требуется отделять подтверждённые сведения о SHA, сообщении, файлах и diff от непроверенных сведений о тестах, артефактах, тегах, релизе и production-поведении.
- Запрещено предлагать номер версии, создание релиза или публикацию без отдельной задачи пользователя и проверки тегов и релизной политики.
- Для изменений XLSX, CSV, PDF, DOCX и других формируемых файлов добавлена обязательная проверка созданного артефакта, а не только import, compile или diff кода.
- Для XLSX закреплена минимальная проверка: формирование тестовой книги, проверка листов и заголовков, значения и `number_format` изменённой ячейки, а для процентов — контрольный сценарий `0.87` → `0.0%` → `87.0%`.
- Уточнено правило для больших файлов: при явном запросе пользователя на полный файл для локальной замены не требуется отдельное согласование декомпозиции, но выдача полного текста разрешена только после подтверждённого чтения исходника.

## KITEZH MAIN 2.22
**Дата:** 11 августа 2026

### Актуализация рабочего протокола

- Обновлена карта проекта KITEZH: `requests_app/`, `api/`, `core/`, `routes/`, `services/`, `app.py` и `db.py`.
- Заменён хрупкий абсолютный путь к WinPython на рабочий подход с интерпретатором из каталога текущего проекта.
- Уточнён приоритет источников: задача пользователя → `KITEZH.md` → подтверждённое состояние GitHub → контекст треда.
- Добавлен строгий read/write protocol для GitHub MCP: читать актуальные файлы перед изменением, раскрывать scope и риски, получать явное подтверждение перед записью, не повторять write после timeout без read-проверки.

### SQLite и безопасный lifecycle

- Добавлен проверенный статус аудита SQLite lifecycle: на момент редакции переход на request-scoped `g.db` является планом, а не заявленной реализованной функцией.
- Зафиксированы границы ownership соединений для Flask request/Jinja, helpers с переданным `conn`, threads, timers, CLI и migrations.
- Добавлен запрет на ручной `close()` shared `g.db` в routes, Jinja context processors и Flask-only helpers после перехода на g-cache.
- Закреплена обязательная проверка call sites перед изменением DB lifecycle или сигнатуры helper.

### Workflow и качество

- Уточнены режимы CODER, GUARDIAN, DEBUGGER, ARCHITECT, REVIEWER, ANALYST, RESPONDER и ДИСПЕТЧЕР.
- Добавлены требования к границам scope, проверяемым утверждениям и минимальному набору запрашиваемых материалов.
- Уточнён checklist: параметризованный SQL, миграции для изменения схемы, `log_action()` для пользовательских действий, проверки imports/route/helper/CLI и отдельная оценка необходимости README update.
- Удалены быстро устаревающие списки issues и неподтверждённые утверждения о текущем состоянии репозитория.
