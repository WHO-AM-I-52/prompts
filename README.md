# 📁 prompts

Коллекция системных промтов для работы с нейросетями.

## Для ИИ

Прочитай раздел «Доступные промты» и предложи подходящий вариант, если пользователь ещё не выбрал режим работы.

Если пользователь явно упоминает **KITEZH**, «Китеж», репозиторий `WHO-AM-I-52/KITEZH`, GitHub MCP в контексте разработки проекта или конкретные файлы KITEZH — сразу загрузи `KITEZH.md` и действуй по его инструкциям. Не требуй повторного выбора промта.

---

## ⚠️ Если GitHub недоступен

Если не удаётся загрузить README или выбранный prompt через GitHub MCP:

```text
Не могу загрузить нужный prompt с GitHub.
Проверьте подключение GitHub в Connectors и доступ к репозиторию.

Если доступна приложенная копия prompt-файла, я использую её как резервную.
Если копии нет, пришлите текст нужного prompt или приложите файл.
```

Не придумывай несуществующие prompts, версии или состояние репозитория.

## 📋 Доступные промты

### 1. KITEZH MAIN 2.23

**Файл:** [KITEZH.md](KITEZH.md)  
**Платформа:** Perplexity Space с GitHub MCP  
**Для чего:** разработка и сопровождение проекта [WHO-AM-I-52/KITEZH](https://github.com/WHO-AM-I-52/KITEZH).

Подходит, когда нужно:

- читать и изменять код KITEZH через GitHub MCP;
- проводить безопасный аудит Flask, SQLite, routes, helpers и migrations;
- вести работу по правилам CODER, GUARDIAN, DEBUGGER, ARCHITECT, REVIEWER, ANALYST, RESPONDER и ДИСПЕТЧЕР;
- готовить локальные правки пользователя как `unified diff`, точечную замену или подтверждённо актуальный полный файл;
- проверять пользовательские commits в read-only режиме, отделяя подтверждённый diff от непроверенных тестов, релиза и production-поведения;
- проверять сформированные XLSX, CSV, PDF, DOCX и другие артефакты, когда изменение затрагивает экспорт;
- соблюдать подтверждения перед записью, точные границы scope и проверяемый workflow GitHub;
- работать с `main` без непроверенных допущений о состоянии репозитория.

**Требует:** подключённый GitHub MCP для работы с актуальным состоянием репозитория. При недоступности MCP можно использовать доступную резервную копию `KITEZH.md`, но нельзя утверждать непроверенные сведения о GitHub.

## 🚀 Как использовать

### Через Perplexity Space

1. Подключите GitHub в разделе Connectors.
2. Откройте Space с этим репозиторием или попросите ИИ прочитать `README.md`.
3. Выберите нужный prompt — либо явно укажите KITEZH-задачу.
4. Для KITEZH ИИ сначала читает `KITEZH.md`, затем актуальные файлы проекта через GitHub MCP.

Пример:

> Прочитай `KITEZH.md` из `WHO-AM-I-52/prompts`. Нужно проверить lifecycle SQLite в репозитории `WHO-AM-I-52/KITEZH`.

### Вручную

1. Выберите prompt по таблице ниже.
2. Скопируйте текст нужного `.md` файла в начало диалога или приложите его файлом.
3. Укажите задачу и ограничения.

- название;
- назначение и ограничения;

- примеры задач, на которых его нужно проверить.

Не добавляйте в issue пароли, API-ключи, токены или персональные данные.
